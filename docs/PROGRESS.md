## 1. 한 줄로

**화면 앞에 사람이 앉아 있어야 돌던 것을, 사람이 없어도 돌고 문제가 생기면

알람 · 자동 복구 · 물리 모니터링 · 문제 런 관리가 붙어 **하나의 사슬**이 됐다.

## 5. 확인한 것 / 확인하지 않은 것

**실측으로 확인한 것**

- 24시간 로테이션이 기록을 잃지 않는다 — 수정 직전 커밋과 A/B 하여 증상 재현까지
- 후처리가 실시간을 따라잡는다 — `FADC = SADC = Merged = PRD` 로 수가 정확히 일치
- 이동·백업이 **내용까지** 맞는다 — 개수가 아니라 `rsync -c` 체크섬 대조
- 모니터링이 분석 체인과 **같은 답**을 낸다 — single 목록 비트 단위 일치, 페어링 8개 수 전부 일치
- 알람·메일 전 경로 — 책임자 1명 + 전문가 6명에게 실제 발송
- 자동 USB 복구 — 하드웨어를 건드리지 않고 10종 시험 통과
- 문제 런 격리가 파이프라인을 푼다 — run 4293 이 실제로 `/Data_ssd` → `/scratch` 를 완주

- 10G 링크 — `/scratch` 읽기 838 · 쓰기 534 MB/s, 오류 0 (08-26)
- 경희대 백업 경로의 병목이 **바깥에 있다** — 병렬 스트림 시험으로 확정 (08-26)

**아직 확인하지 못한 것 (정직하게)**

- **10G 에서 dataflow 3단계가 실제로 도는 것.** 지금 수치는 산술이다.
  체크섬 대조 비용과 후처리의 `/scratch` 대 `/Data_ssd` 차이도 다시 재야 한다
- **자동 USB 복구는 실제 장애에서 통하지 않았다.** 08-26 에 처음 겪었는데
  진단이 TCB 로그를 안 보고 오류 패턴도 안 맞아 `not-usb` 로 물러났다.
  게다가 답이 `usbreset` 이 아니라 **물리적 전원 재투입**이었다 (§11.119·§11.120)
- 외부 스피커가 현장에서 실제로 들리는지 (사람이 확인해야 한다)
- jumbo frame(MTU 9000) — 양쪽 끝이 같아야 해서 아직 시도하지 않았다

## 6. 남은 것

**사이트 조치가 필요한 것 — 우리가 못 고친다**

| 무엇 | 왜 급한가 |
|---|---|
| ~~**100 Mb 스토리지 링크**~~ | **08-26 해결.** 10 Gb 로 교체. 쓰기 7.7 → 534 MB/s (§11.115) |
| **경희대 백업 경로가 143 Mbps 에서 막혀 있다** | 이 PC 의 1 Gb 카드는 **13%만 쓰인다** — 랜카드 교체는 값어치가 없다. 스트림을 5배로 늘려도 총량이 10%밖에 안 늘고, **두 번 재서 같은 값**이다. 로컬 셰이핑·TCP 버퍼는 배제했다. **다음 차례 : 사용자가 중간 장비를 뺀 뒤 `scripts/netcheck.sh` 로 재측정** (§11.121) |
| ~~**NFS 가 인터넷에 열려 있다**~~ | **08-25 해결.** export 0건임을 확인하고 방화벽에서 닫았다 (§11.100) |
| **`/scratch/LOG` 의 깨진 디렉터리 항목** | 특정 이름만 EIO. 08-20·08-21·08-23·08-24 네 번 PRD 구멍을 냈다. **08-25 에 로그 구조를 갈아 증상은 멎었다**(§11.103, run 4306·4307 결손 0) — 남은 것은 결함 자체다. `xfs_repair` 는 마운트를 풀어야 하고 114 TB 에 완전한 백업이 없으니 서두를 일은 아니다. **이제 `ssh store` 로 원격 진단이 가능하다** (§11.118) |
| **TCB/FADC 보드가 걸리면 사람이 가야 한다** | `usbreset` 으로 안 풀리는 경우가 있고, 그때는 **보드 전원 재투입**뿐이다. 원격으로 할 수 없다 (§11.119) |
